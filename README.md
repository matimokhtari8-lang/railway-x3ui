# پنل 3x-ui (تم بنفش-مشکی) + ربات تلگرام فروش کانفینگ

این پروژه از دو سرویس مستقل تشکیل شده که هر کدوم جدا روی Railway دیپلوی می‌شن:

1. **`panel/`** — همون دیپلوی قبلی 3x-ui روی Railway، با یک تغییر: از طریق nginx یک
   فایل CSS بنفش-مشکی به صفحه‌ی پنل تزریق می‌شه.
2. **`telegram-bot/`** — یک ربات تلگرام کاملاً جدا و مستقل که با API پنل صحبت می‌کنه و
   روی یک اینباند از‌پیش‌ساخته، برای هر کاربر کلاینت/کانفینگ جدید می‌سازه. کاربر نهایی
   فقط دکمه می‌زنه؛ لازم نیست چیزی درباره‌ی اینباند بدونه یا وارد پنل بشه.

---

## بخش ۱: پنل (`panel/`)

دقیقاً مثل قبل عمل کنید — این سه فایل رو (به‌همراه `custom-theme.css` جدید) در ریشه‌ی
یک ریپازیتوری گیت‌هاب قرار بدید و در Railway دیپلوی کنید. هیچ مرحله‌ی اضافه‌ای نیست؛
تم به‌صورت خودکار روی صفحه‌ی `/managepanel/` اعمال می‌شه.

اگر بعد از دیپلوی جایی از پنل هنوز رنگ قبلی مونده بود:
1. صفحه رو با Ctrl+F5 رفرش کنید (کش مرورگر).
2. با کلیک راست → Inspect روی همون بخش، اسم کلاس CSS رو پیدا کنید و به
   `panel/custom-theme.css` اضافه کنید، بعد دوباره Push/Deploy کنید.

مراحل ساخت اینباند دقیقاً مثل قبل (VLESS / ws / پورت 8080) هست — همونی که قبلاً
ساختید همینه که ربات تلگرام هم ازش استفاده می‌کنه.

---

## بخش ۲: ربات تلگرام (`telegram-bot/`)

### مراحل راه‌اندازی

1. یک ربات تلگرام از [@BotFather](https://t.me/BotFather) بسازید و توکنش رو بردارید.
2. آی‌دی اینباندی که در پنل ساختید رو پیدا کنید (از URL صفحه‌ی ویرایش اینباند در پنل،
   یا از طریق `/panel/api/inbounds/list`).
3. فایل `.env.example` رو کپی و به `.env` تغییر نام بدید و مقادیر واقعی خودتون
   (توکن ربات، آدرس پنل، یوزر/پس پنل، شماره‌ی اینباند، دامنه، مسیر ws) رو پر کنید.
4. این پوشه (`telegram-bot/`) رو در یک ریپازیتوری گیت‌هاب جدا (یا همون ریپو، در یک
   ساب‌فولدر) قرار بدید.
5. در Railway یک **سرویس جدید** (New Service) از همین ریپازیتوری بسازید — این باید
   یک سرویس *جدا* از سرویس پنل باشه، چون یک پروسه‌ی دائمی مستقله.
6. متغیرهای محیطی داخل `.env.example` رو در تنظیمات همون سرویس (Variables) وارد کنید.
7. اگر می‌خواید لیست «کانفینگ‌های من» بین ری‌دیپلوی‌ها پاک نشه، یک Volume به مسیر
   `/data` وصل کنید (دقیقاً مثل کاری که برای `/etc/x-ui` در پنل انجام دادید).

### تجربه‌ی کاربر نهایی

کاربر روی `/start` می‌زنه و این دکمه‌ها رو می‌بینه:

- 🟣 **ساخت کانفینگ جدید** → مدت اعتبار (۷ / ۳۰ / ۹۰ روز / نامحدود) و حجم ترافیک
  (۱۰ / ۵۰ / ۱۰۰ گیگ / نامحدود) رو با دکمه انتخاب می‌کنه، ربات خودش کلاینت رو روی
  پنل می‌سازه و لینک + QR کد رو می‌فرسته.
- 📦 **کانفینگ‌های من** → لیست کانفینگ‌هایی که همون کاربر قبلاً ساخته.
- ℹ️ **راهنما** → توضیح کوتاه نحوه‌ی استفاده از لینک.

هیچ‌جا از کاربر نمی‌خواد اینباند بسازه یا وارد پنل بشه — همه‌چیز پشت‌صحنه با API
انجام می‌شه.

### دستور ادمین

`/stats` (فقط برای آی‌دی‌های داخل `ADMIN_IDS`) تعداد کل کانفینگ‌های ساخته‌شده رو نشون
می‌ده.

### نکته‌ی امنیتی

یوزر/پسورد پنل و توکن ربات فقط در متغیرهای محیطی سرویس Railway نگه داشته می‌شن،
هیچ‌جا در کد هاردکد نشدن. پسورد پنل رو حتماً از `admin/admin` پیش‌فرض تغییر داده
باشید.
